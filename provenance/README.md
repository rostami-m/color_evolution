# Provenance and release changes

The completed production study ran from the immutable `mps_20261120` runtime. `production_source_hashes.json` records its 43 Python files; all 43 were checked against the original runtime on 24 November 2026. The original runtime, raw results, queue logs, CPU predecessor and checkpoints remain in the research archive. They are not silently edited or relabeled by this release.

`production_design.json` is the historical scientific design. Its original one-worker resource description was subsequently superseded by an eight-worker scheduler with a shared six-core CPU allowance; training settings did not change. `production_requirements.lock` captures installed versions. `data_manifest.json` records source URLs, hashes, MAT variables, crop bounds and partition membership. Foster measured bands are 410–710 nm; the model grid is 400–700 nm, repeating the 410-nm endpoint at 400 nm. Bank clipping [0.001,1.2] and trial clipping [0.01,1.1] are explicit historical conventions, not assertions about a physical upper bound.

The release promotes the production `revision` functions. Necessary helper functions move from historical modules to `revision.spectral`, `revision.legacy_metrics`, and `revision.ecological_proxies`. Their numerical definitions are retained. Old competing experimental runners, the synthetic default entry point, and stale machine-specific queue instructions are removed from the active tree. Git history retains the prior publication. The release adds portable data/run paths, explicit backend selection, manifest overwrite protection, current packaging, bounded queue use, and portable post-run scripts. Documentation distinguishes unsupported biological interpretations from computed measurements; scientific outcomes are not changed to agree with a narrative.

`published_source_hashes.json` records copied numerical files before private absolute paths were replaced with `PROJECT` / `PRODUCTION_RUN`. The published bundle's own `manifest.json` records hashes after that textual path sanitization. No numerical result is altered by sanitization. Per-seed results are independent network seeds within a fixed data partition, not independent environmental samples.

The release test report and configuration-equivalence report are generated during the publication audit. Regenerating figures from the bundle is distinct from rerunning analyses on completed job records, which is distinct from training a new replication. The README gives commands for all three levels.
